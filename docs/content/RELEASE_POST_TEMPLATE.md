# memware 发布内容模板

> 使用规则：先填完整事实母稿，再按渠道压缩。删除所有未验证段落和占位符；不要把计划写成已交付。

## 1. 事实母稿

### 标题

`memware vX.Y.Z：<一个用户可感知的结果>`

### 用户问题

谁在什么任务中遇到了什么阻碍？这个问题为什么值得现在解决？

### 本次变化

- 用户现在可以：`<能力与结果>`
- 与上一版本相比：`<行为差异>`
- 不变的边界：`<平台、数据、兼容性或未支持能力>`

### 证据

- 版本：`vX.Y.Z`
- 支持平台：`<已实际验证的平台>`
- 验证命令：`<真实命令>`
- 测试/烟测结果：`<结果与日期>`
- Release：`<链接>`
- 文档：`<链接>`

### 3 分钟体验

```sh
# 填写已在干净环境验证的最短命令；不要提前发布不可用的 npx 命令。
```

完成标志：`<例如 memory_status 返回 ready>`。

### 升级与兼容性

- 从版本 `<旧版本>` 升级：`<步骤>`
- 破坏性变化：`<无，或具体说明>`
- 回滚：`<步骤>`

### 数据与隐私

本次变化是否改变数据保存位置、发送内容、模型服务、日志或删除行为？若没有，写“无变化”，不要省略。

### 唯一 CTA

`<安装 / 复现案例 / 提交反馈，三选一>`

## 2. GitHub Release 版

结构保持为：

1. 一句话结果
2. 3 项以内的重点变化
3. 安装或升级命令
4. 兼容性与数据边界
5. 完整 Changelog 链接

## 3. 社区短帖版

建议控制为四段：

1. 用户问题：`<一句>`
2. 新结果：`<一句>`
3. 证据：`<一个截图、数字或可复现链接>`
4. CTA：`<一个动作>`

不要使用“革命性”“最强”“零风险”“完全隐私”等无法证实的形容词。
